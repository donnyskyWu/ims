## 0. 约定

### 0.1 编号
`TPL` 模板、`SUB` 填报、`AUD` 审核（FLOW）、`STAT` 统计、`UP`/`BG`。

### 0.2 范围

| 类别 | 内容 |
|------|------|
| 侧栏 | 「协同与成长 / 数据上报」3 叶 + 填报二级页：上报模板 `/ims/report/template`、填报单管理 `/ims/report/submission`、完成率统计 `/ims/report/stat`；填报页 `/ims/report/submit/:pendingId`（无独立叶子） |

### 0.3 权限码

| 权限码 | 授予 |
|--------|------|
| `ims:report:template:query/write` | R1；R3 财务线；R4 业务线；R9 只读 |
| `ims:report:submit:write` | **仅** R2/R3/R5/R6/R10（被指派）；**R5 菜单必挂**【已定】 |
| `ims:report:submission:query` | R1/本线/填报人本人/R9 |

### 0.4 错误码 1121～1127
1121 勾稽字段不存在；1122 勾稽失败；1123 模板+周期+填报人+作者+账号唯一；1124 退回原因必填；1125 3 轮升级；1126 非本线审核人；1127 作者与账号非同 IP 组池；另：填报人角色不合规 **1128**【本清单裁定，S-01】；1001；1500/1501/1504。

### 0.5 表
`ims_report_template`（version、fields_schema、cross_check、assignee_mode、biz_line、status）；`ims_report_template_assignee`；`ims_report_submission`（submission_no、template_id、version、period、submitter、author_id、account_id、data_json、status DRAFT/SUBMITTED/IN_REVIEW/APPROVED/REJECTED、is_on_time、flow_instance_id）；`ims_report_audit_record`；`ims_report_stat`。FLOW 实例在 B4 表；**逻辑关联 flow_instance_id，无物理外键**。

### 0.6 FLOW 衔接（已定）
1. 填报人提交 → 校验通过 → 写 submission SUBMITTED → 调用 B4 引擎按模板业务线启动 `REPORT_REVIEW`（传入 submissionId、bizLine、节点候选人按模板线路由）。
2. 状态 IN_REVIEW；工作台/我的流程出现待办；深链打开本模块审核抽屉。
3. 通过/退回：完成 FLOW 任务 + 写 audit_record；退回 → REJECTED + 填报人重报待办；通过且流程结束 → APPROVED（计入 BR-106 分子）。
4. 模块内 `PUT /report/audit/{id}` 为**门面**，内部必须走 FLOW task complete，禁止旁路改状态【S-02】。
5. B4 预置模板已在 B4 批次；本批只绑定业务键与表单变量，不改 FLOW 设计器核心。

### 0.7 完成率（BR-106）
`completeRate = approvedCount / shouldSubmitCount`  
- 应提交：按模板周期 × 有效填报人（资格过滤后；不合规待办作废不计分母，B083）。  
- 分子：状态 APPROVED。  
- 迟交（isOnTime=false）仍可进分母；通过后进分子。
