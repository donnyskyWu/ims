## 旧版功能测试用例

`旧版功能测试用例/` 来自历史 TC（TC-00～TC-23 及打包 zip），只作参考。新用例仍按批次写在 `modules/<批次>/`，不把旧用例当作新系统验收依据。

## 开发方法

顺序固定为：**B0a 框架 → B0b 前端基础层 → 按模块批次（B1～B29）**。B0a 与 B0b 合起来对应模块清单中的 B0；B1 起与 `03-模块清单与依赖顺序.md`、`05-开发计划.md` 的批次一一对应。

每个批次开工前先写功能点清单和用例，评审通过后再编码。功能点清单是开发依据；清单没写清的地方先补清单，再写代码。增删改查骨架用脚手架生成，业务规则在生成后补写。同一时刻只安排一个编码会话写代码。

## 测试方法

- **框架（B0a）用单测**：按 `modules/B0a-框架/02-单测用例.md` 写成自动化单测，外部系统 Mock。
- **前端基础层（B0b）**在组件示例页上按用户操作验证，见 `modules/B0b-前端基础层/02-验证用例.md`。
- **功能模块用业务 E2E**：按用户操作写（哪个账号、点哪个菜单、填什么、页面上看到什么），不按接口写。用例放在 `modules/<批次>/`，例如 `02-业务E2E用例.md`。
- **开发提测前只跑接口单测和路由冒烟**（本批页面路由可打开、主接口返回正确、无权限用户看不到菜单）。业务 E2E 由测试在测试环境执行；通过的用例只记通过，失败用例才截图；修复后只回归已登记的 bug。

原系统测试方法见 `产品文档/测试方案/`。新用例按批次写在 `modules/<批次>/`。
