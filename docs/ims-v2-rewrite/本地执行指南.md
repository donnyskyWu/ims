## 2. 工作方法（已定，勿改）

1. **一个模块一批、一次做完**：每批交给一个编码会话一次做完，不拆小切片、不多路并行，批次严格串行。
2. **先审材料再编码**：每批由产品经理写 `01-功能点清单`、`02-业务E2E用例`、`03-评审记录`，zhang wu 审过之前不编码。
3. **按功能点实现**：严格按 01 清单逐条实现，每批产出对照表 `v2/docs/B<n>-M<nn>-对照表.md`（功能点 → 实现位置 → 状态）。
4. **提测前只做快速验证**：只跑相关的接口单测、路由冒烟、`vue-tsc --noEmit && vite build`。**不跑**全量 Playwright 和业务 E2E，这部分由测试工程师按用户操作执行。
5. **提测与测试**：编码完成后开 draft PR，Grok Bot 汇报后由 zhang wu 决定是否合入；合入后部署 8090，测试工程师 B、C 按 02 用例在界面操作验证并登记缺陷；修复后只回归登记过的 bug。
6. **需求问题**：先由产品经理裁定，裁定不了交给 zhang wu。
7. **全部完成后做 UAT**，通过即交付；UAT 允许遗留的 P2 不超过 5 个。

## 3. 硬约束（每批都适用）

1. 只改 `v2/`，旧代码（`ims-backend/`、`ims-web/`）不动。
2. API 前缀 `/admin-api/ims/`；所有 ID 以字符串传给前端（雪花 ID 超过 2^53）。
3. 主库 `imsV2.0`；Alembic 只加不减；**不建物理外键**；保证 `alembic heads` 只有一个 head（多 head 先加空 merge revision）。
4. 无权限的按钮不渲染；离职员工完全禁止登录；权限按权限码配置，不按角色名硬编码。
5. 前端只用 B0b 已建的通用组件，不新造通用组件。
6. 分支从最新 `main` 拉，命名 `feat/b<n>-m<nn>-<简称>`；PR 先开 draft，标题含批次号和模块号（如「B8：M08 IP 组」）。
7. 密钥、数据库密码、测试密码一律不写进仓库或文档，只通过环境变量注入。
8. 外部环境：钉钉、内容 AI、数据采集用真实环境，其余用模拟接口；Football 直播表在开发测试环境用替身表。

## 4. 本地执行 B8 的步骤

1. 拉最新代码并建分支：
   ```bash
   git checkout main && git pull
   git checkout -b feat/b8-m08-ip-group
   ```
2. 确认 Alembic 单 head（在 `v2/` 后端目录）：`alembic heads`
3. 在 Cursor 里打开仓库，新开一个 Agent 对话，把第 5 节的「开工提示词」整段贴进去。材料已在仓库里：`docs/ims-v2-rewrite/modules/B8-M08IP组/`。
4. Agent 完成后检查：对照表已生成，相关单测、路由冒烟、构建通过。
5. 推送并开 draft PR：
   ```bash
   git push -u origin feat/b8-m08-ip-group
   ```
   在 GitHub 上开 draft PR 到 `main`，标题「B8：M08 IP 组」。
6. 在 Grok Bot 聊天里说一声「B8 PR 开好了」，后面的审查、合入、部署 8090、通知产品经理准备 B9、交测试由 Grok Bot 接手。
