## ADR-IMS-008 · 角色与岗位权限模型收敛（权限模型重构 + 原型 + 全量文档同步）

**用户诉求（逐字）**：
1. 「权限管理 —— 岗位模板 是做什么用的，用户故事是什么」（先问清岗位模板定位）
2. 「感觉和角色体系很重合啊，是不是应该合并为角色？钉钉同步过来岗位，如果没有角色，则自动创建角色」
3. 「可以，按照你的建议推荐来吧；然后同步优化 PRD、UI原型」

### 架构结论（核心决策）

**角色（SYS-002）= 权限唯一载体**；岗位模板（AUTH-003）降级为「钉钉岗位 → 角色 自动供给规则」。
- 真正重复的**不是概念**，而是**两套并行权限矩阵**（SYS-002 菜单权限码 vs AUTH-003 功能点 R/W/D）。
- 岗位 ≠ 角色：来源/基准/版本/触发/外部契约都不同，不能合并概念，只能收敛「权限明细载体」到角色。
- 角色吸收：菜单权限码 + **功能点 R/W/D（新 `ims_role_perm_detail`）** + **dataScope 数据范围** + **钉钉岗位绑定**（新列 `dingtalk_position`）。
- 岗位模板保留版本管理（POS-R2）与 `grant_role_ids`；`ims_position_template_perm` 表 DEPRECATED。

**钉钉自动建角色 8 条护栏 G1-G8**：
- G1 失败关闭（空权限 ≠ 放行，绝不「无角色=全通」）
- G2 `source=DINGTALK_AUTO`；G3 `status=PENDING_CONFIG`
- G4 推送 R1 待办；G5 1:1 唯一（POS-R1）
- G6 幂等 upsert（按 `dingtalkPosition`）
- G7 岗位消失且无用户时归档（POS-R3）；G8 全量审计

## 修复 · 查询工具向导控件样式不统一（下拉框/文本框）

**用户诉求**：「查询工具的 配置页面的下拉框/文本框等样式不同，请优化」

### 根因（关键）

向导内容渲染在抽屉内的 **`.qt-wiz`** 容器中，**不带 `.page-query-tool` / `.bi0-qb-root` 祖先**；而查询工具的下拉/输入/文本框样式规则全部挂在这两个祖先下（`.page-query-tool .qt-qctl`、`.page-query-tool .qb-form select`、`.drawer-b .page-query-tool …`）。因此向导「配置载荷」步里的下拉框/表内 select 落到原生浏览器默认外观，与「基本信息」步的 `.fld` 表单控件（34px 圆角）风格打架。

### 修复（原型 CSS，仅新增一段，不改 JS）

在 `</style>` 前新增一段 **`.drawer-b .qt-wiz`** 控件基线，对齐 `.fld` 基线（34px / 8px 圆角 / 13px / `1px var(--line2)`）：
- 覆盖 `.qt-wiz` 内所有 `input:not([radio/checkbox])` / `select` / `textarea` / `.qt-qctl`；
- 含 `:focus`（蓝边 + 3px 光晕）、`[readonly]/[disabled]`（灰底）、`.err`（红边）；
- `textarea` 单独 min-height 70px；
- `.qt-wiz .qb-row .btn{height:34px}`——与控件同行的「关键词·筛选」按钮高度对齐。
